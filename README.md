## 🎯 Problem Statement

**The Challenge:** Professionals across sales, recruiting, market research, and business intelligence spend enormous amounts of time manually collecting structured data from the web — copying job listings, company details, conference sponsors, competitor pricing, VC portfolios — into spreadsheets. This is slow, error-prone, inconsistent, and doesn't scale.

**The Solution:** DataPulse AI transforms any natural-language business question into a complete, validated, exportable dataset. You describe what you need in plain English; the AI orchestrates an entire multi-stage research pipeline that searches the web, retrieves source content, extracts structured records, deduplicates them, scores quality, and delivers a clean dataset — all fully automated.

## ✨ Key Features

### 🤖 AI-Driven Research Pipeline (8 Stages)
```
Natural Language Prompt
  → Stage 1: AI Research Planner (dynamic schema + search strategy)
  → Stage 2: Web Search (Serper / Brave / Google CSE)
  → Stage 3: Content Retrieval (multi-source, 3 concurrent)
  → Stage 4: Evidence-Grounded Extraction (strictly from source content)
  → Stage 5: Coverage Evaluation (AI decides on additional passes)
  → Stage 6: Validate + Deduplicate (field validation, review flagging)
  → Stage 7: Quality Scoring (5-dimensional metrics)
  → Stage 8: Finalize Dataset (provenance-traced, export-ready)
```

### 🔍 Real Web Research
- Provider-agnostic search layer — swap between Serper.dev, Brave, or Google CSE without code changes
- Search queries dynamically generated by AI for your specific request
- Avoids login-walled sites; targets open job boards, career sites, public directories
- Up to 3 iterative research passes for better coverage

### 🎯 Evidence-Grounded Extraction
- AI extracts data strictly from retrieved source content — no hallucination of records
- Every field value tagged with extraction method (source-derived, AI-inferred, demo-generated)
- Full provenance chain: search query → source URL → extracted snippet → field value
- Snippet-based fallback for JavaScript-rendered SPAs that resist scraping

### 📊 5-Dimensional Data Quality Scoring
| Dimension | What it measures |
|-----------|-----------------|
| **Completeness** | % of required fields filled across all records |
| **Validity** | % of fields passing type/format validation rules |
| **Uniqueness** | % non-duplicate records after deduplication |
| **Evidence Coverage** | % of values with a direct source snippet |
| **Confidence** | Average extraction confidence across all fields |

### 🔬 Interactive Evidence Graph
Click any record to open a side panel showing:
- Field-by-field confidence scores and extraction method dots
- Clickable source snippets that link to the original URL
- Review workflow: Accept / Reject / Verify with audit notes
- Inline field editing with change history tracking

### 📤 Export Ready
- One-click **CSV** export (current filtered view)
- One-click **JSON** export (includes metadata: confidence, review status, evidence count)
- **Re-run** any research task and see what changed

### 🌊 Live Research Monitor
- Animated progress bar (per-stage status)
- Per-step execution timeline with timing
- Scrolling execution log console (live, color-coded by level)
- Source tracking panel (fetch status per URL)

### 📜 Research History
- Searchable archive of all tasks
- Filter by status: All / Running / Completed / Failed
- Record counts and timestamps at a glance

## 🏗️ Architecture

```
src/
├── app/
│   ├── page.tsx                     # Home: prompt input + examples + pipeline viz
│   ├── history/page.tsx             # Research history with search + filters
│   ├── tasks/[id]/page.tsx          # Live task monitor (real-time polling)
│   ├── tasks/[id]/results/page.tsx  # Results: table + evidence + quality + logs
│   └── api/tasks/
│       ├── route.ts                 # POST (create), GET (list)
│       └── [id]/
│           ├── route.ts             # GET (full task + records + evidence)
│           ├── rerun/route.ts       # POST (re-run same prompt)
│           └── records/[id]/route.ts # PATCH (review action or field edit)
├── components/
│   ├── Nav.tsx                      # Sticky glassmorphism navigation bar
│   └── EvidenceGraph.tsx            # Evidence inspection slide panel
└── lib/
    ├── orchestrator.ts              # 8-stage pipeline coordinator
    ├── quality.ts                   # Scoring + deduplication + validation
    ├── ai/
    │   ├── client.ts                # Gemini model client with fallback chain
    │   ├── planner.ts               # Stage 1: Research plan from prompt
    │   └── extractor.ts             # Stage 4: Source-grounded extraction
    ├── search/providers.ts          # Search provider abstraction
    ├── retrieval/fetcher.ts         # HTTP fetch + sanitization + snippet fallback
    └── db/client.ts                 # File-backed JSON store (atomic writes)
```

### Data Storage (File-Backed, No Database Required)
```
data/
├── index.json            # Fast task index (id, title, status, timestamps)
├── tasks/{id}.json       # Task metadata, plan, quality, summary
├── logs/{id}.jsonl       # Append-only execution log
├── sources/{id}.json     # Web sources with fetch status
├── evidence/{id}.json    # Evidence items (snippets, URLs, confidence)
└── records/{id}.json     # Processed records with full field values
```

## 🚀 Setup & Installation

### Prerequisites
- **Node.js** 18+
- **npm** 9+
- A free **Gemini API key**
- A free **Serper API key** (for real web research)

### Step 1 — Install Dependencies
```bash
cd datapulse-ai
npm install
```

### Step 2 — Configure Environment
Edit `.env.local` in the project root:

```env
# REQUIRED: Get free at https://aistudio.google.com/app/apikey
GEMINI_API_KEY=your_gemini_key_here

# RECOMMENDED: Get free at https://serper.dev (2,500 searches/month)
SERPER_API_KEY=your_serper_key_here

# ALTERNATIVE: Brave Search (2,000/month) — https://api.search.brave.com
# BRAVE_API_KEY=your_brave_key_here

# ALTERNATIVE: Google Custom Search (100/day)
# GOOGLE_CSE_KEY=your_google_key_here
# GOOGLE_CSE_ID=your_cse_id_here
```

### Step 3 — Get Your API Keys

**Gemini API Key:**
1. Go to [aistudio.google.com/app/apikey](https://aistudio.google.com/app/apikey)
2. Click "Create API Key" → copy it into `GEMINI_API_KEY`

**Serper API Key (recommended for real research):**
1. Go to [serper.dev](https://serper.dev)
2. Sign up for free (no credit card) → copy key into `SERPER_API_KEY`

> Without a search API key, DataPulse runs in **Demo Mode**: the AI generates plausible sample records clearly labelled as demo data. Add a search key to get real web research results.

### Step 4 — Run
```bash
npm run dev
```
Open [http://localhost:3000](http://localhost:3000)

## 🔬 Technical Deep-Dives

### AI Model Fallback Chain
DataPulse uses a cascading fallback for maximum reliability under load. (Note: We explicitly use the 3.1/3.5/Flash-Lite models instead of the latest 3.8 models to bypass the strict 20-request/day limits on the 2026 free tier):

```
gemini-3.1-flash-lite    → Primary (extremely high availability, no strict rate limits)
gemini-flash-lite-latest → Secondary (always resolving to fastest lite model)
gemini-flash-latest      → Tertiary (standard tier fallback)
gemini-3.5-flash-lite    → Quaternary (proven stable)
gemini-3.6-flash         → Last resort
  ↓ all fail → wait 4s → retry primary
```

The first successfully responding model is cached for the session. On failure, the cache is cleared and the chain retries from scratch.

### Web Scraping Resilience
Three-layer content strategy:
1. **Full HTML fetch** → Cheerio sanitization (strips scripts, styles, navigation)
2. **Snippet fallback** → If content is too short (SPA/JavaScript sites), use search snippet
3. **Blocked detection** → Auth/paywall redirects are flagged as `blocked`, not `failed`

### Atomic File Writes (Windows Safe)
```
1. Write to temp file:  file.json.tmp.{PID}.{random}
2. If target exists:    fs.copyFileSync(tmp → target)   ← avoids EPERM on Windows
   If new file:         fs.renameSync(tmp → target)
3. On any failure:      fs.writeFileSync(target) direct fallback
4. Always:              cleanup temp file
```

### Deduplication
Compares normalized values of `deduplicationKeys` (from research plan) per record. Normalization = lowercase + trim + strip punctuation. First occurrence kept; duplicates flagged `isDuplicate: true`.

### Quality Score Formula
```
completeness = mean(filled_required_fields / required_fields) × 100
validity     = mean(valid_fields / total_fields) × 100
uniqueness   = unique_records / total_records × 100
evidence     = mean(has_any_evidence ? 1 : 0) × 100
confidence   = mean(all_field_confidence_scores)
```

## 🏆 What Makes This Hackathon-Worthy

### Innovation
- **Evidence-grounded extraction** — AI cannot fabricate records; it must ground every extraction in actual retrieved content
- **Dynamic schema generation** — No hardcoded output structure; the AI creates a custom field schema per request
- **Provider-agnostic search** — One clean interface for any search provider, swappable via env var

### Engineering Quality
- TypeScript end-to-end with strict types
- Windows-safe atomic file writes (EPERM resilient)
- Batch DB operations (`createMany`) for disk I/O efficiency
- Concurrent source fetching (configurable parallelism)
- Model fallback chain with session caching

### User Experience
- Real-time research monitor with live logs
- Interactive evidence drill-down per record
- Human-in-the-loop review workflow (accept/reject/verify)
- Inline field editing with correction tracking
- One-click CSV & JSON export

### Transparency & Trust
- Every record has a confidence score
- Every field shows its extraction method (dot color code)
- Full provenance: field → snippet → URL → search query
- Demo mode clearly labelled when API not configured
